# Мобильный органайзер домашних растений

Приложение «Листва» помогает вести домашнюю коллекцию растений и планировать уход за ними. Интерфейс полностью на русском языке.

## Возможности

- Добавление растений с названием, видом и комнатой; редактирование и удаление карточек.
- Календарь полива, подкормки и пересадки: выбор дня, переключение месяцев и возврат к сегодняшней дате.
- Добавление процедур, изменение даты, растения и вида процедуры, удаление ненужных записей.
- Автоматическое обновление названий в календаре после переименования растения. При удалении растения удаляются все связанные процедуры.
- Цветовые статусы полива: красный — срок просрочен, янтарный — полив сегодня, зелёный — будущий срок или растение полито сегодня. Статус также подписан текстом.
- Кнопка «Полить сегодня» и отмена ошибочной отметки.

Срок полива определяется по ближайшей невыполненной процедуре в календаре. Отметка полива закрывает сегодняшние и просроченные поливы растения и появляется в календаре за сегодня. Будущие процедуры остаются в расписании. Следующий срок автоматически не придумывается: его нужно запланировать в календаре.

**Хранение данных:** пока используется память приложения. После полного закрытия и повторного запуска, а также Hot Restart, изменения сбрасываются и загружается начальная коллекция. Постоянной базы данных и синхронизации с сервером пока нет.

## Что понадобится

1. **Git** — для скачивания проекта и получения обновлений: [установка Git](https://git-scm.com/downloads).
2. **Flutter SDK** — для сборки и запуска приложения. Проверенная версия — Flutter **3.47.4** с Dart **3.13.3**. Dart входит в Flutter, отдельно устанавливать его не нужно. Следуйте [официальной инструкции Flutter](https://docs.flutter.dev/install/manual).
3. **Android Studio** — редактор кода, Android SDK и управление эмуляторами: [скачать Android Studio](https://developer.android.com/studio).
4. **Android-эмулятор или Android-телефон** для запуска.
5. Интернет для первой загрузки SDK, зависимостей и образа эмулятора. Само приложение работает без сети.

Основной вариант запуска — Android. Есть также веб-версия для Chrome. Конфигурации Windows desktop и iOS в этом репозитории не созданы.

## 1. Подготовьте Flutter

Распакуйте Flutter SDK в отдельную папку, вне проекта. Желательно, чтобы путь не содержал пробелов и кириллицы.

Добавьте подпапку `bin` установленного Flutter в переменную окружения `PATH`, как описано в инструкции установки. Затем заново откройте терминал и Android Studio.

Проверьте в терминале:

```shell
git --version
flutter --version
```

Обе команды должны вывести версии. Если команда `flutter` не найдена, проверьте `PATH` и перезапустите терминал.

## 2. Подготовьте Android Studio

1. Запустите Android Studio и завершите мастер первоначальной настройки.
2. Откройте **Settings → Plugins → Marketplace**, установите плагин **Flutter** и согласитесь на установку **Dart**. Перезапустите IDE. На macOS настройки находятся в меню Android Studio.
3. Откройте **Tools → SDK Manager**. На стартовом экране этот пункт доступен через **More Actions → SDK Manager**.
4. Установите Android SDK Platform **API 36**, Android SDK Build-Tools **36.0.0**, Android SDK Platform-Tools и Android SDK Command-line Tools. Для виртуального устройства установите также Android Emulator.
5. Выполните в терминале:

```shell
flutter doctor --android-licenses
flutter doctor -v
```

Прочитайте и примите лицензии необходимых SDK. Исправьте проблемы, отмеченные в разделе **Android toolchain**. При первой сборке Gradle может дополнительно скачать нужные компоненты, включая NDK.

Если Flutter не видит SDK в нестандартной папке, укажите свой путь:

```shell
flutter config --android-sdk "ПУТЬ_К_ANDROID_SDK"
```

Текст `ПУТЬ_К_ANDROID_SDK` замените расположением SDK из окна SDK Manager. Подробнее: [настройка Android для Flutter](https://docs.flutter.dev/platform-integration/android/setup).

## 3. Скачайте проект с GitHub

Откройте терминал в папке, где хотите хранить проекты, и выполните:

```shell
git clone https://github.com/Jewilor/home-plants-organizer.git
cd home-plants-organizer
flutter pub get
```

Первая команда скачивает репозиторий, вторая переходит в его папку, третья загружает зависимости.

В Android Studio выберите **Open** и откройте папку `home-plants-organizer`, содержащую `pubspec.yaml`. Открывайте корень проекта целиком, а не вложенную папку `android`.

Если IDE попросит Flutter SDK, укажите папку установленного SDK — ту, внутри которой находятся `bin` и `packages`.

Дождитесь загрузки проекта и завершения индексации.

## 4. Подготовьте устройство

### Эмулятор

1. В Android Studio откройте **Tools → Device Manager**.
2. Нажмите **Create Virtual Device** или кнопку **+**, выберите модель телефона.
3. Скачайте подходящий образ Android: для компьютера x64 — x86_64, для Apple Silicon — ARM64.
4. Завершите создание устройства и нажмите **▶** рядом с ним.
5. Дождитесь рабочего стола Android. Первая загрузка может занять несколько минут.

Чтобы телефон отображался внутри IDE, включите **Settings → Tools → Emulator → Launch in the Running Devices tool window**, затем откройте **View → Tool Windows → Running Devices**.

### Настоящий телефон

Включите режим разработчика и отладку по USB на Android-телефоне, подключите его кабелем и подтвердите разрешение отладки на самом телефоне. В Windows для некоторых моделей требуется USB-драйвер производителя.

Проверьте доступные устройства:

```shell
flutter devices
```

Телефон или эмулятор должен появиться в списке Android-устройств.

## 5. Запустите приложение

В верхней панели Android Studio выберите **Android-устройство**, откройте `lib/main.dart` и нажмите **Run ▶**. IDE соберёт приложение, установит его и откроет. Устанавливать APK вручную для разработки не нужно.

Не выбирайте `Windows (desktop)`: для него нет конфигурации сборки. Ошибка `No Windows desktop project configured` означает, что нужно переключить целевое устройство на Android.

Альтернативный запуск из терминала в корне проекта:

```shell
flutter run
```

Если устройств несколько, выполните `flutter devices`, скопируйте идентификатор Android-устройства и укажите его вместо `DEVICE_ID`:

```shell
flutter run -d DEVICE_ID
```

Для веб-проверки при установленном Chrome:

```shell
flutter run -d chrome
```

## Работа с приложением

1. На вкладке «Мой сад» нажмите «Добавить растение». Название обязательно, вид и комната необязательны. При желании сразу запланируйте первый полив.
2. Меню **⋮** на карточке позволяет изменить растение или удалить его вместе с расписанием.
3. В календаре выберите день и нажмите «Добавить процедуру». Укажите растение, тип ухода и дату.
4. Через **⋮** у процедуры можно изменить её или удалить. После переноса приложение покажет новую дату.
5. Нажмите «Полить сегодня» на карточке растения. Она станет зелёной с подписью «Полито сегодня». Для исправления случайного нажатия используйте «Отменить отметку».

Для проверки просрочки создайте полив на вчерашнюю дату. Карточка станет красной. Отметьте полив сегодня, проверьте запись в календаре, затем отмените отметку — исходная просрочка восстановится.

## Сборка и сохранение APK

В терминале Android Studio, открытом в корне проекта:

```shell
flutter build apk --debug
```

Готовый файл: `build/app/outputs/flutter-apk/app-debug.apk`.

Скопируйте его в удобную папку для хранения или передачи: каталог `build` может пересоздаваться. На запущенный эмулятор APK можно перетащить мышью. На Android-телефоне откройте скопированный APK; при запросе системы разрешите установку для используемого файлового менеджера.

Для оптимизированной сборки:

```shell
flutter build apk --release
```

Результат: `build/app/outputs/flutter-apk/app-release.apk`. В текущем проекте release-сборка использует отладочный ключ. Для публикации в магазине необходимо отдельно настроить собственную подпись: [подготовка Android-релиза](https://docs.flutter.dev/deployment/android).

## Обновление проекта и приложения

Если вы меняли код, сначала сохраните изменения в Git. Затем получите обновления:

```shell
git pull --ff-only
flutter pub get
```

Повторно нажмите **Run** для обновления приложения на выбранном устройстве. Если используете APK, соберите новый файл и установите его поверх предыдущего. Для обновления поверх старой версии должны совпадать идентификатор приложения и ключ подписи.

Во время разработки **Hot Reload ⚡** применяет многие изменения Dart-кода без сброса состояния. **Hot Restart** перезапускает Dart-приложение и очищает текущие данные в памяти. Изменения Android-конфигурации требуют полной остановки и нового запуска.

## Где находится код

| Путь | Содержание |
| --- | --- |
| `lib/main.dart` | Запуск приложения, тема и русская локаль |
| `lib/models/` | Растения, процедуры и состояния полива |
| `lib/data/` | Начальная коллекция |
| `lib/viewmodels/` | Управление данными, календарём и отметками полива |
| `lib/views/` | Каталог, календарь и формы редактирования |
| `test/` | Автоматические проверки |
| `android/` | Конфигурация сборки Android |
| `web/` | Конфигурация веб-запуска |
| `pubspec.yaml` | Зависимости и версия приложения |

Файлы в `build` и `.dart_tool` создаются автоматически; вручную редактировать их не нужно.

Для проверки кода:

```shell
flutter analyze
flutter test
```

# Мобильный органайзер домашних растений

Приложение «Листва» помогает вести домашнюю коллекцию растений и планировать уход за ними. Интерфейс полностью на русском языке.

## Возможности

- Добавление растений с названием, видом, комнатой и семейством; редактирование и удаление карточек.
- Календарь полива, подкормки и пересадки: выбор дня, переключение месяцев и возврат к сегодняшней дате.
- Добавление процедур, изменение даты, растения и вида процедуры, удаление ненужных записей.
- Автоматическое обновление названий в календаре после переименования растения. При удалении растения удаляются все связанные процедуры.
- Цветовые статусы полива: красный — срок просрочен, янтарный — полив сегодня, зелёный — будущий срок или растение полито сегодня. Статус также подписан текстом.
- Кнопка «Полить сегодня» и отмена ошибочной отметки.
- Еженедельное повторение процедур с выбранной даты.
- Журнал фактически выполненных поливов, подкормок и пересадок с датой и примечанием.
- Условия содержания: собственный текст при добавлении и редактировании растения или сведения из локального справочника.
- Получение регламента ухода из сетевой энциклопедии, его сохранение и просмотр без интернета.
- Создание расписания полива с выбранным интервалом от одного до 365 дней.
- Локальные уведомления Android: включение, выбор времени, просмотр очереди и проверочное уведомление.
- Справочники семейств растений и типов удобрений с названием и значком; добавление, редактирование и удаление записей.
- Выбор удобрения для подкормки в календаре. Используемую запись справочника можно удалить после снятия связи с растением или процедурой.
- Добавление названия и вида растения по тексту с этикетки: камера, галерея или встроенные изображения для эмулятора. Вид заполняется, если найден на этикетке; результат можно исправить перед сохранением.

Срок полива определяется по ближайшей невыполненной процедуре. Отметка полива закрывает сегодняшние и просроченные поливы растения и записывает выполненный уход в журнал. Будущие процедуры остаются в расписании. При включённом повторении «Еженедельно» следующий срок появляется через семь календарных дней. Изменение или удаление серии действует на все её повторения; журнал фактически выполненного ухода сохраняется.

**Хранение данных на Android:** растения, условия содержания, журнал и расписание сохраняются в SQLite, а семейства и удобрения — в Hive CE. После закрытия и повторного запуска данные восстанавливаются. Начальная коллекция создаётся один раз; удалённые растения не появляются заново. Дождитесь сообщения «Изменения сохранены на устройстве» перед закрытием. Синхронизации с сервером нет.

## Что понадобится

1. **Git** — для скачивания проекта и получения обновлений: [установка Git](https://git-scm.com/downloads).
2. **Flutter SDK** — для сборки и запуска приложения. Проверенная версия — Flutter **3.47.5** с Dart **3.13.4**. Dart входит в Flutter, отдельно устанавливать его не нужно. Следуйте [официальной инструкции Flutter](https://docs.flutter.dev/install/manual).
3. **Android Studio** — редактор кода, Android SDK и управление эмуляторами: [скачать Android Studio](https://developer.android.com/studio).
4. **Android-эмулятор или Android-телефон** для запуска.
5. Интернет для первой загрузки SDK, зависимостей и образа эмулятора. Каталог, календарь и сохранённые справки работают без сети. Получение нового регламента требует интернета.

Основной вариант запуска — Android. В веб-демонстрации для Chrome доступны каталог, календарь и журнал с данными в памяти; постоянные базы, справочники семейств и удобрений и распознавание этикеток проверяются в Android-приложении. Конфигурации Windows desktop и iOS в этом репозитории не созданы.

## 1. Подготовьте Flutter

Распакуйте Flutter SDK в отдельную папку, вне проекта. Желательно, чтобы путь не содержал пробелов и кириллицы.

Добавьте подпапку `bin` установленного Flutter в переменную окружения `PATH`, как описано в инструкции установки. Затем заново откройте терминал и Android Studio.

Проверьте в терминале:

```shell
git --version
flutter --version
```

Обе команды должны вывести версии. Если команда `flutter` не найдена, проверьте `PATH` и перезапустите терминал.

## 2. Подготовьте Android Studio

1. Запустите Android Studio и завершите мастер первоначальной настройки.
2. Откройте **Settings → Plugins → Marketplace**, установите плагин **Flutter** и согласитесь на установку **Dart**. Перезапустите IDE. На macOS настройки находятся в меню Android Studio.
3. Откройте **Tools → SDK Manager**. На стартовом экране этот пункт доступен через **More Actions → SDK Manager**.
4. Установите Android SDK Platform **API 36**, Android SDK Build-Tools **36.0.0**, Android SDK Platform-Tools и Android SDK Command-line Tools. Для виртуального устройства установите также Android Emulator.
5. Выполните в терминале:

```shell
flutter doctor --android-licenses
flutter doctor -v
```

Прочитайте и примите лицензии необходимых SDK. Исправьте проблемы, отмеченные в разделе **Android toolchain**. При первой сборке Gradle может дополнительно скачать нужные компоненты, включая NDK.

Если Flutter не видит SDK в нестандартной папке, укажите свой путь:

```shell
flutter config --android-sdk "ПУТЬ_К_ANDROID_SDK"
```

Текст `ПУТЬ_К_ANDROID_SDK` замените расположением SDK из окна SDK Manager. Подробнее: [настройка Android для Flutter](https://docs.flutter.dev/platform-integration/android/setup).

## 3. Скачайте проект с GitHub

Откройте терминал в папке, где хотите хранить проекты, и выполните:

```shell
git clone https://github.com/Jewilor/home-plants-organizer.git
cd home-plants-organizer
flutter pub get
```

Первая команда скачивает репозиторий, вторая переходит в его папку, третья загружает зависимости.

В Android Studio выберите **Open** и откройте папку `home-plants-organizer`, содержащую `pubspec.yaml`. Открывайте корень проекта целиком, а не вложенную папку `android`.

Если IDE попросит Flutter SDK, укажите папку установленного SDK — ту, внутри которой находятся `bin` и `packages`.

Дождитесь загрузки проекта и завершения индексации.

## 4. Подготовьте устройство

### Эмулятор

1. В Android Studio откройте **Tools → Device Manager**.
2. Нажмите **Create Virtual Device** или кнопку **+**, выберите модель телефона.
3. Скачайте подходящий образ Android: для компьютера x64 — x86_64, для Apple Silicon — ARM64.
4. Завершите создание устройства и нажмите **▶** рядом с ним.
5. Дождитесь рабочего стола Android. Первая загрузка может занять несколько минут.

Чтобы телефон отображался внутри IDE, включите **Settings → Tools → Emulator → Launch in the Running Devices tool window**, затем откройте **View → Tool Windows → Running Devices**.

### Настоящий телефон

Включите режим разработчика и отладку по USB на Android-телефоне, подключите его кабелем и подтвердите разрешение отладки на самом телефоне. В Windows для некоторых моделей требуется USB-драйвер производителя.

Проверьте доступные устройства:

```shell
flutter devices
```

Телефон или эмулятор должен появиться в списке Android-устройств.

## 5. Запустите приложение

В верхней панели Android Studio выберите **Android-устройство**, откройте `lib/main.dart` и нажмите **Run ▶**. IDE соберёт приложение, установит его и откроет. Устанавливать APK вручную для разработки не нужно.

Не выбирайте `Windows (desktop)`: для него нет конфигурации сборки. Ошибка `No Windows desktop project configured` означает, что нужно переключить целевое устройство на Android.

Альтернативный запуск из терминала в корне проекта:

```shell
flutter run
```

Если устройств несколько, выполните `flutter devices`, скопируйте идентификатор Android-устройства и укажите его вместо `DEVICE_ID`:

```shell
flutter run -d DEVICE_ID
```

Для веб-проверки при установленном Chrome:

```shell
flutter run -d chrome
```

## Работа с приложением

1. На вкладке «Мой сад» нажмите «Добавить растение». Название обязательно, вид и комната необязательны. При желании сразу запланируйте первый полив.
2. Меню **⋮** на карточке позволяет изменить растение или удалить его вместе с расписанием.
3. В календаре выберите день и нажмите «Добавить процедуру». Укажите растение, тип ухода и дату.
4. Для повторения нажмите «Еженедельно» в форме процедуры или первого полива растения. Повторы появляются в тот же день недели, начиная с выбранной даты. Через **⋮** у процедуры можно изменить её или удалить. После переноса приложение покажет новую дату.
5. Нажмите «Полить сегодня» на карточке растения. Она станет зелёной с подписью «Полито сегодня». Для исправления случайного нажатия используйте «Отменить отметку».

Для проверки просрочки создайте полив на вчерашнюю дату. Карточка станет красной. Отметьте полив сегодня, проверьте запись в журнале ухода, затем отмените отметку — исходная просрочка восстановится.

Откройте «Справка и журнал ухода» на карточке растения. Кнопка «Записать уход» добавляет выполненную процедуру. Будущую дату выбрать нельзя. Историю можно отфильтровать по виду ухода.

Для добавления с этикетки нажмите «Сканировать этикетку». Выберите снимок камеры, изображение из галереи или один из встроенных образцов. Распознаются латинские ботанические названия; русское название и комнату можно ввести вручную. Проверьте поля перед кнопкой «Добавить в мои растения». Распознавание выполняется без сети. После добавления открывается сетевой поиск по распознанному имени. Для загрузки регламента требуется интернет. Если нужное растение не найдено, уточните поле «Название или вид растения»; сведения другого вида автоматически не подставляются.

## Регламент ухода и напоминания

В карточке растения откройте «Справка и журнал ухода» и нажмите «Получить регламент ухода». Проверьте название, источник и полученные сведения. Выберите первый полив и интервал, затем нажмите «Сохранить регламент». При включённом создании расписания прежний план полива этого растения заменяется; фактическая история ухода остаётся в журнале. Можно сохранить только справку, выключив «Создать расписание полива». Ручные условия содержания хранятся отдельно.

Для запуска без регистрации по умолчанию используется учебная энциклопедия с пятью растениями. Данные действительно загружаются по HTTP через REST API GitHub. Название передаётся в параметре `q`, GitHub возвращает коллекцию, а приложение ищет точное совпадение в ней. Учебные интервалы служат для демонстрации расписания. Это не ответ сервиса Perenual.

Для подключения Perenual получите собственный ключ на [странице сервиса](https://perenual.com/docs/api) и запустите проект:

```shell
flutter run -d DEVICE_ID --dart-define=PERENUAL_API_KEY=ВАШ_КЛЮЧ
```

Для APK используйте тот же параметр:

```shell
flutter build apk --debug --dart-define=PERENUAL_API_KEY=ВАШ_КЛЮЧ
```

Ключ не добавляйте в Git. Для другого учебного сервера предусмотрен параметр `--dart-define=PLANT_API_URL=https://адрес/путь`; формат ответа приведён в `demo_api/encyclopedia.json`. В Perenual выполняются запрос поиска по имени и запрос подробных данных выбранного вида. Если сервис не возвращает числовой интервал, введите его самостоятельно; отсутствующие сведения о влажности не выдумываются.

Нажмите значок колокольчика в верхней панели и включите «Напоминать об уходе». Разрешите уведомления в запросе Android. Выберите время. Очередь содержит ближайшие процедуры за 30 дней, не более 64 уведомлений, и обновляется при запуске и изменении календаря. Завершённые процедуры исключаются. Переименование растения обновляет текст, удаление растения отменяет его будущие напоминания. Android может задержать доставку в режиме энергосбережения.

Для полива можно использовать общее время всех растений или включить «Отдельно для каждого растения». В отдельном режиме задайте время на карточках растений в разделе «Напоминания»: например, фикусу 08:00, монстере 18:30. Растение без отдельной настройки использует общее время. Кнопка «Использовать общее время» снимает отдельную настройку. Переключение к общему режиму сохраняет выбранные часы для последующего возврата. Даты и интервалы полива задаются в календаре; время подкормки и пересадки остаётся общим.

Кнопка «Проверить уведомление» отправляет уведомление сразу. Откройте верхнюю панель уведомлений эмулятора. Для проверки будущего расписания посмотрите очередь на экране «Напоминания». Если разрешение было отклонено, включите его в системных настройках Android для приложения «Листва» и нажмите «Обновить напоминания».

## Сборка и сохранение APK

В терминале Android Studio, открытом в корне проекта:

```shell
flutter build apk --debug
```

Готовый файл: `build/app/outputs/flutter-apk/app-debug.apk`.

После отправки изменений в GitHub проверки и сборка также выполняются автоматически. Откройте вкладку **Actions**, выберите завершённый запуск **Android verification and APK** и скачайте архив **home-plants-organizer-debug** из раздела **Artifacts**. Для скачивания войдите в GitHub. Распакуйте архив: внутри находится `app-debug.apk`. Облачная сборка имеет свой отладочный ключ; поверх установленного локального APK её можно установить только при совпадении подписей. Локальные сборки продолжайте выполнять через Android Studio или терминал.

Скопируйте его в удобную папку для хранения или передачи: каталог `build` может пересоздаваться. На запущенный эмулятор APK можно перетащить мышью. На Android-телефоне откройте скопированный APK; при запросе системы разрешите установку для используемого файлового менеджера.

Для оптимизированной сборки:

```shell
flutter build apk --release
```

Результат: `build/app/outputs/flutter-apk/app-release.apk`. В текущем проекте release-сборка использует отладочный ключ. Для публикации в магазине необходимо отдельно настроить собственную подпись: [подготовка Android-релиза](https://docs.flutter.dev/deployment/android).

## Обновление проекта и приложения

Если вы меняли код, сначала сохраните изменения в Git. Затем получите обновления:

```shell
git pull --ff-only
flutter pub get
```

Повторно нажмите **Run** для обновления приложения на выбранном устройстве. Если используете APK, соберите новый файл и установите его поверх предыдущего. Для обновления поверх старой версии должны совпадать идентификатор приложения и ключ подписи.

Во время разработки **Hot Reload ⚡** применяет многие изменения Dart-кода без сброса состояния. **Hot Restart** перезапускает Dart-приложение. На Android сохранённые данные загружаются из базы, а в браузере текущие данные в памяти сбрасываются. Изменения Android-конфигурации требуют полной остановки и нового запуска.

## Где находится код

| Путь | Содержание |
| --- | --- |
| `lib/main.dart` | Запуск приложения, тема и русская локаль |
| `lib/models/` | Растения, процедуры и состояния полива |
| `lib/data/` | Начальная коллекция |
| `lib/viewmodels/` | Управление данными, календарём и отметками полива |
| `lib/views/` | Каталог, календарь, формы, справка, журнал и распознавание |
| `lib/services/` | SQLite, Hive CE, HTTP-энциклопедия, уведомления и распознавание изображений |
| `assets/` | Локальная ботаническая справка и изображения этикеток |
| `demo_api/` | Опубликованные ответы учебной сетевой энциклопедии |
| `integration_test/` | Проверка Android и получение снимков |
| `test/` | Автоматические проверки |
| `android/` | Конфигурация сборки Android |
| `web/` | Конфигурация веб-запуска |
| `pubspec.yaml` | Зависимости и версия приложения |

Файлы в `build` и `.dart_tool` создаются автоматически; вручную редактировать их не нужно.

Для проверки кода:

```shell
flutter analyze
flutter test
```


Проверка Android с настоящим распознаванием трёх этикеток и сохранением снимков:

```shell
flutter drive --keep-app-running --driver=test_driver/lab2_screenshots.dart --target=integration_test/lab2_demo_test.dart -d ИДЕНТИФИКАТОР_УСТРОЙСТВА
```

Проверка постоянного хранения и снимки интерфейса:

```shell
flutter drive --keep-app-running --driver=test_driver/lab3_screenshots.dart --target=integration_test/lab3_demo_test.dart -d ИДЕНТИФИКАТОР_УСТРОЙСТВА
```

После проверки вернитесь к обычному приложению командой `flutter run -t lib/main.dart -d ИДЕНТИФИКАТОР_УСТРОЙСТВА`.


Проверка сетевого регламента и уведомлений с сохранением снимков:

```shell
flutter drive --keep-app-running --driver=test_driver/lab4_screenshots.dart --target=integration_test/lab4_demo_test.dart -d ИДЕНТИФИКАТОР_УСТРОЙСТВА
```

Проверка сохранённых данных после нового запуска процесса:

```shell
flutter drive --keep-app-running --driver=test_driver/lab4_screenshots.dart --target=integration_test/lab4_demo_test.dart --dart-define=LAB4_RESTORE_CHECK=true -d ИДЕНТИФИКАТОР_УСТРОЙСТВА
```

Проверки используют отдельный каталог данных `lab4_verification`. Параметр `--keep-app-running` сохраняет установленное приложение после завершения; без него Flutter удаляет тестовое приложение вместе с его данными. Для возврата к обычному приложению снова запустите `lib/main.dart`.

# Разъяснение кода проекта для защиты лабораторной работы № 1

## Назначение проекта

Проект представляет собой мобильное приложение «Мобильный органайзер домашних растений». В первой лабораторной работе реализована функциональная часть варианта 7: каталог комнатных растений, календарь процедур ухода и визуальное отображение необходимости полива.

Приложение написано на языке Dart с использованием Flutter. Интерфейс построен декларативно: в методе `build` описывается требуемое дерево виджетов, а Flutter перестраивает изменившиеся элементы после обновления состояния.

## Структура проекта

Файл `lib/main.dart` является точкой входа. Функция `main` запускает приложение с помощью `runApp`. Класс `PlantApp` задаёт русскую локаль, тему Material 3, цветовую схему и начальный экран `GardenScreen`.

Файл `lib/models/plant.dart` содержит модели предметной области. Класс `Plant` описывает растение: идентификатор, название, вид, помещение, дату следующего полива и дату последнего выполненного полива. Класс `CareProcedure` описывает процедуру: растение, дату, вид ухода и состояние выполнения. Перечисление `CareType` содержит три вида процедур: полив, подкормка и пересадка. Перечисление `WateringStatus` используется для выбора состояния карточки растения.

Файл `lib/data/demo_garden.dart` содержит исходные демонстрационные данные. Он нужен для того, чтобы после запуска приложение сразу показывало растения и процедуры, предусмотренные для проверки интерфейса. Данные этого этапа хранятся в оперативной памяти.

Файл `lib/viewmodels/garden_view_model.dart` реализует состояние приложения. Класс `GardenViewModel` наследуется от `ChangeNotifier`. Он хранит списки растений и процедур, выбранный день календаря и отображаемый месяц. После изменения состояния вызывается `notifyListeners`, поэтому интерфейс получает новые значения и перестраивается.

Файл `lib/views/garden_screen.dart` содержит основной экран. Он отображает вкладку «Мой сад», вкладку «Календарь», карточки растений, календарную сетку и действия пользователя. Файл `lib/views/editors.dart` содержит формы добавления и редактирования растений и процедур.

## Реализация главного экрана

После запуска класс `GardenScreen` создаёт экземпляр `GardenViewModel`. Состояние передаётся во вспомогательные части экрана. В нижней части используется `NavigationBar`, с помощью которого пользователь переключается между каталогом и календарём.

Каталог строится из списка `model.plants`. Для каждого элемента создаётся карточка растения. В карточке выводятся название, вид, помещение и срок полива. Цвет карточки определяется результатом метода `plant.statusAt(model.today)`.

Если дата полива раньше текущей даты, возвращается состояние `WateringStatus.overdue`. Для него используется красный фон и надпись «Полив просрочен». Если срок совпадает с текущим днём, применяется состояние `today` и янтарное оформление. Для будущей даты используется состояние `upcoming` и зелёное оформление. Если пользователь уже отметил полив сегодня, применяется состояние `watered`. Если дата не задана, используется состояние `unscheduled`.

Кнопка «Полить сегодня» вызывает метод `toggleWateredToday`. После этого процедура получает дату выполнения, а карточка показывает, что полив выполнен. Повторное нажатие отменяет отметку. Будущие процедуры при отметке не закрываются, поскольку полив сегодня не должен изменять будущий срок.

## Реализация операций с растениями

Метод `savePlant` используется и для добавления, и для редактирования. Если идентификатор не передан, создаётся новое растение и ему назначается новый идентификатор. Если идентификатор передан, находится существующая запись и её значения заменяются.

Перед сохранением название очищается от начальных и конечных пробелов. Пустое название считается ошибкой. Также проверяется длина названия, вида и помещения. После успешного сохранения вызывается `notifyListeners`.

Метод `deletePlant` удаляет растение по идентификатору. Одновременно из списка процедур удаляются все записи, у которых указан этот идентификатор. Благодаря этому после удаления растения в календаре не остаются процедуры, связанные с несуществующей записью.

## Реализация календаря

Календарь использует два значения состояния: `selectedDate` — выбранный день и `visibleMonth` — месяц, который сейчас показан. Метод `selectDay` изменяет выбранный день и месяц. Методы `changeMonth` и `goToToday` обеспечивают переход между месяцами и возврат к текущей дате.

Метод `proceduresOn` возвращает процедуры, дата которых совпадает с выбранным днём. Сравнение выполняется функцией `sameDay`, которая удаляет время из объектов `DateTime` и сравнивает только год, месяц и число. Это предотвращает ошибку, при которой одинаковые даты с разным временем считались разными.

При добавлении процедуры метод `saveProcedure` проверяет существование растения и запрещает создание дубликата с тем же растением, видом ухода и датой. При изменении процедуры сохраняется отметка выполнения, если растение, вид и дата остались прежними. Если эти значения изменились, отметка снимается, поскольку фактически изменена сама процедура.

Метод `plantFor` получает растение по идентификатору процедуры. Поэтому календарь всегда показывает актуальное название растения. При редактировании названия обновляется одна запись растения, и календарь автоматически использует новое значение. При удалении растения связанные процедуры удаляются методом `deletePlant`.

## Связь частей по архитектуре

В проекте применена архитектура Model–View–ViewModel. Модель описывает данные и правила определения состояния полива. Объект представления модели хранит изменяемое состояние и предоставляет методы действий: сохранение и удаление растений, сохранение и удаление процедур, выбор дня и отметку полива. Представление читает состояние объекта представления модели и вызывает его методы в ответ на нажатия пользователя.

Такое разделение позволяет не размещать правила предметной области внутри виджетов. Например, правило определения просрочки находится в `Plant.statusAt`, а не в коде оформления карточки. Это упрощает проверку и дальнейшее добавление постоянного хранения данных.

## Как объяснить демонстрацию

При запуске сначала открывается вкладка «Мой сад». На ней можно показать список растений и карточку с красным фоном. Красный фон означает, что дата полива находится в прошлом. Затем следует нажать «Полить сегодня» и показать изменение текста карточки. После этого можно открыть меню карточки, выбрать редактирование и изменить название растения.

Далее открывается вкладка «Календарь». В календаре выбирается день с процедурой, после чего ниже отображается связанное растение. Для демонстрации управления расписанием нажимается «Добавить процедуру», выбираются растение, вид ухода и дата. Созданную запись можно изменить или удалить. При удалении растения его процедуры исчезают из календаря автоматически.

## Возможные вопросы преподавателя

**Почему выбран Flutter?** Flutter позволяет создавать декларативный интерфейс на языке Dart и запускать приложение на Android. Для данной работы он заменяет связку Swift и SwiftUI из исходного задания.

**Где хранятся данные?** На первом этапе данные хранятся в оперативной памяти. Демонстрационные записи загружаются при создании `GardenViewModel`. Постоянная база данных относится к следующему этапу проекта.

**Как интерфейс узнаёт об изменениях?** `GardenViewModel` наследуется от `ChangeNotifier`. После изменения списка или выбранной даты вызывается `notifyListeners`, а `ListenableBuilder` перестраивает зависящую часть интерфейса.

**Как определяется просрочка?** Метод `statusAt` сравнивает дату следующего полива с текущей датой без учёта времени. Если дата меньше текущей, растение считается просроченным.

**Почему календарь обновляется после переименования растения?** Процедура хранит идентификатор растения, а не копию его названия. При отображении календарь каждый раз получает актуальное растение через `plantFor`.

**Что происходит при удалении растения?** Удаляется запись растения и все процедуры с таким идентификатором. Это предотвращает появление в календаре процедур без связанного растения.

**Какие проверки выполнены?** Выполнены автоматические тесты операций с датами, календарём, растениями, процедурами и отметкой полива. Команда `flutter analyze` завершается без замечаний, а команда `flutter test` успешно выполняет десять тестов.

## Итог защиты

В первой лабораторной работе реализован каталог комнатных растений, интерактивный календарь процедур, цветовые индикаторы необходимости полива, операции добавления, изменения и удаления растений и процедур, а также отметка выполненного полива за текущий день. Код разделён на модели, объект представления модели и представление, что соответствует выбранной архитектуре Model–View–ViewModel.
